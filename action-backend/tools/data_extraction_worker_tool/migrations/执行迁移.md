# 数据抽取 Worker 数据库迁移指南

## ⚠️ 错误原因

如果看到以下错误：
```
Unconsumed column names: extraction_schema, total_file_size
```

说明数据库中缺少这些字段，需要执行数据库迁移。

---

## 🚀 执行迁移（3种方式）

### 方式 1: 使用 Python 脚本（推荐）

在**项目的 Python 虚拟环境**中执行：

```bash
cd backend/tools/data_extraction_worker_tool/migrations
python run_migrations.py
```

**预期输出**：
```
数据抽取 Worker 数据库迁移
============================================================
✓ 已连接到数据库: your_database

执行迁移文件: create_tables.sql
============================================================

[1/9] ALTER TABLE `data_extraction_history` ADD COLUMN `total_file_size` BIGI...
  ✓ 成功

[2/9] ALTER TABLE `data_extraction_history` ADD COLUMN `extraction_schema` JS...
  ✓ 成功

...

============================================================
✓ 迁移完成!
============================================================
```

---

### 方式 2: 直接使用 MySQL 命令行

```bash
mysql -u your_username -p your_database < backend/tools/data_extraction_worker_tool/migrations/create_tables.sql
```

**参数说明**：
- `your_username`: 你的MySQL用户名（如 root）
- `your_database`: 你的数据库名

**示例**：
```bash
mysql -u root -p smartebm < backend/tools/data_extraction_worker_tool/migrations/create_tables.sql
```

---

### 方式 3: 使用 MySQL 客户端工具

1. 打开 MySQL Workbench / Navicat / DBeaver 等工具
2. 连接到数据库
3. 打开文件：`backend/tools/data_extraction_worker_tool/migrations/create_tables.sql`
4. 执行SQL语句

---

## 📋 迁移内容

### 1. 修改 `data_extraction_history` 表

添加以下字段：
- ✅ `total_file_size` - 文件总大小（BIGINT）
- ✅ `extraction_schema` - 抽取schema（JSON）
- ✅ `output_log_path` - 输出日志路径（VARCHAR）

添加以下索引：
- ✅ `idx_session_id` - session_id唯一索引
- ✅ `idx_user_id` - user_id索引
- ✅ `idx_status` - status索引

### 2. 创建 `data_extraction_file_status` 表

用于断点续传的文件状态跟踪表。

---

## ✅ 验证迁移

执行以下SQL验证字段是否添加成功：

```sql
-- 检查 data_extraction_history 表结构
DESCRIBE data_extraction_history;

-- 检查 data_extraction_file_status 表是否创建
SHOW TABLES LIKE 'data_extraction_file_status';

-- 查看 data_extraction_file_status 表结构
DESCRIBE data_extraction_file_status;
```

**预期结果**：

`data_extraction_history` 表应该包含：
- `total_file_size` (bigint)
- `extraction_schema` (json)
- `output_log_path` (varchar(512))

`data_extraction_file_status` 表应该存在且包含：
- id, session_id, file_name, file_url, file_index, local_path
- status, error_message, processing_duration
- created_at, completed_at

## 🔧 常见问题

### Q: 提示 "Duplicate column name"
**A**: 这是正常的！说明字段已经存在，迁移脚本会自动跳过。

### Q: 提示 "Duplicate key name"
**A**: 这是正常的！说明索引已经存在，迁移脚本会自动跳过。

### Q: Python 找不到 sqlalchemy 模块
**A**: 请确保在项目的虚拟环境中执行：
```bash
# 激活虚拟环境
source venv/bin/activate  # Linux/Mac
# 或
venv\Scripts\activate     # Windows

# 然后执行迁移
cd backend/tools/data_extraction_worker_tool/migrations
python run_migrations.py
```

### Q: 迁移失败怎么办？
**A**:
1. 检查数据库连接配置（`backend/config/env.py`）
2. 确认MySQL服务正在运行
3. 检查用户权限（需要ALTER TABLE权限）
4. 手动执行SQL（方式2或方式3）
